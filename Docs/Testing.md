# Testing — Local runs and CI

This document explains how to compile the project and run Unity Test Runner tests locally and in CI.

Local test runner helper

At the repository root there is a PowerShell script `run-unity.ps1` which can be used to force a Unity script compile or run EditMode/PlayMode tests.

Examples (PowerShell):

- Force a compile (no tests):

```powershell
.\run-unity.ps1
```

- Run EditMode tests:

```powershell
.\run-unity.ps1 -RunEditModeTests
```

- Run both EditMode and PlayMode tests (runs EditMode then PlayMode):

```powershell
.\run-unity.ps1 -RunEditModeTests -RunPlayModeTests
```

By default the script attempts to detect the Unity executable via the `UNITY_PATH` environment variable, or by reading `ProjectSettings/ProjectVersion.txt` and probing common install locations. You can also pass `-UnityPath` to the script to point to the editor directly.

Output

Test results and logs are written to the `TestResults/` directory (git-ignored): XML result files,
`unity.log` for compile-only runs, and `unity-EditMode.log` / `unity-PlayMode.log` for test runs.
The script prints a pass/fail summary per platform and returns a non-zero exit code when Unity fails,
any test fails, or a run produces no results file (usually a compile error — check the log).

Notes on how the script drives Unity (both were bugs before M1, and made every run "pass" silently):

- `Unity.exe` is a GUI-subsystem program, so PowerShell's `&` does not wait for it. The script uses
  `Start-Process` and waits for the exit code, up to `-TimeoutSeconds` (default 600).
- Test runs must **not** pass `-quit`: Unity then quits before the test runner starts.

## Rebuilding the FirstCase scene

`Assets/_Project/Scenes/FirstCase.unity` (and its NavMesh, placeholder materials and
`Data/PlayerMovement.asset` if missing) is generated by `Assets/_Project/Editor/FirstCaseSceneBuilder.cs`.
In the editor: **RpgGame → Rebuild FirstCase Scene**. From the command line:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.3.5f2\Editor\Unity.exe' -batchmode -nographics -projectPath . `
  -executeMethod RpgGame.Editor.FirstCaseSceneBuilder.BuildFromCommandLine -logFile TestResults\build-scene.log
```

(As above, `&` returns before Unity finishes — wait for the Unity process to exit before running tests.)

## Play-mode screenshot

`ScreenshotCapture` is an `[Explicit]` PlayMode fixture: normal runs skip it. `CaptureFirstCaseInPlayMode`
walks the player into the study, clicks the kitchen, and writes `TestResults/Screenshots/FirstCase-play.png`;
`CaptureInteractInPlayMode` inspects the wall clock and hovers the desk, writing `M2-Interact.png` (the UI canvas
is switched to Screen Space – Camera for the shot, because overlay UI doesn't render into a RenderTexture). It needs a graphics
device, so run it without `-nographics`:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.3.5f2\Editor\Unity.exe' -batchmode -projectPath . -runTests `
  -testPlatform PlayMode -testFilter RpgGame.Tests.PlayMode.ScreenshotCapture `
  -testResults TestResults\screenshot.xml -logFile TestResults\screenshot.log
```
